# Building the MRB-100 Centurion

The mod is two files that work only as a pair: `Centurion.dll`, the BepInEx plugin built from `src/Centurion`, and `centurion_<version>.nobp`, the Blueprinter bundle built by the Unity project in `unity/`. The bundle is authored from the mesh exports in `art/export`, `art/export_awacs` and `art/export_cockpit`, so you don't need Blender unless you change the model.

The build has only been run on the developer's machine. If a step fails on yours, open an issue with the step and the error.

## What you need

- Windows, PowerShell 7, and Git with Git LFS (the skin textures are LFS files: run `git lfs pull` if a PNG opens as a short text file).
- The .NET SDK (8 or later).
- Python 3.9 or later, available as `python`, for export hash checks.
- Unity Editor **2022.3.62f2**.
- A purchased copy of Nuclear Option **0.34.2** with BepInEx 5 installed in it. The build reads the game's assemblies and BepInEx's from there. If the game isn't at `D:\SteamLibrary\steamapps\common\Nuclear Option`, set `NUCLEAR_OPTION_DIR` to its folder.
- An export of your game install from **AssetRipper 2.0.0** (Script Content Level **Level 1**, Script Export Format **Decompilation**). The repository holds no game assets; the build clones stock settings from your local import.

## Prepare the Unity project (once)

1. Open the `unity` folder in Unity Hub and let Unity restore its packages. Blueprinter Editor is pinned to commit `9a4a8e509480cbcde901a577985d5e9cbc570d91` in `unity/Packages/manifest.json`.
2. Open **Blueprinter > Project Setup** and enter game version `0.34.2`.
3. Choose **Import Game Assemblies** and select your `NuclearOption.exe`. Let Unity finish compiling and reload.
4. Import the game assets from your AssetRipper export's `ExportedProject/Assets` folder through Blueprinter's importer. They land in `Assets/Blueprinter/_donotship`, where the build looks stock assets up by path.
5. Import **TMP Essentials** when Unity asks.
6. Close Unity. The build runs it in batch mode and refuses while an editor has the project open.

Imported game assets, assemblies and Unity caches stay local and are ignored by git. Never commit them.

## Build

From the repository root:

```powershell
pwsh -NoProfile -File tools/Build-Centurion.ps1
```

It checks every export against `art/export-manifest.json`, builds the plugin, copies it and BepInEx's assemblies into the Unity project, authors the aircraft from those pinned exports, and builds the bundle. It never re-exports a cached AWACS scene. The last line is the verdict, `G0.1 PASS: build/centurion_<version>.nobp ...` or `G0.1 FAIL: <why>`. Unity's logs stay in `build/logs`. Pass `-UnityPath <Unity.exe>` if it can't find Unity 2022.3.62f2.

The build rewrites authored prefabs under `unity/Assets/Blueprinter/Mods/centurion`. Unity regenerates their object IDs. Release checks exempt those prefab files, but check the bytes of FBX, textures and other authored assets before and after building.

## Install your build

Close the game, then copy `build/Centurion.dll` and `build/centurion_<version>.nobp` into `BepInEx/plugins/baanish.centurion/` in the game folder. Blueprinter 2.0.1 must be installed and enabled. `BepInEx/LogOutput.log` names the version on load: `MRB-100 Centurion <version> (baanish.centurion)`.

## Change the model

The model is generated by Python scripts in `art/blender` that run in Blender 5.2. Each script's docstring has its full options. From the repository root, in order:

1. `blender --background --factory-startup --python art/blender/build_centurion.py -- --step 6.1 --span retracted,extended` writes the blockout to `.cache/art/blockout_s61`.
2. `blender --background --factory-startup --python art/blender/detail_centurion.py -- --group all --span retracted` writes the detailed aircraft to `.cache/art/m4`.
3. `blender --background --factory-startup --python art/blender/awacs_mount.py` writes the AWACS beam to `.cache/art/awacs_mount`.
4. `blender --background --factory-startup --python art/blender/status_silhouette.py` redraws the cockpit and HUD line art into the mod folder.
5. Export the aircraft with `blender --background --factory-startup --python tools/export_blockout.py -- --blend .cache/art/m4/centurion_m4_retracted.blend`. Export an intentionally changed AWACS or cockpit scene with the same command, adding `--out art/export_awacs` or `--out art/export_cockpit` and its scene's `--blend` path. All three use the same FBX metadata scrubber.
6. Run `python tools/scrub_fbx.py` to clean existing Unity copies too, then `python tools/export_manifest.py --write`. Review and commit the manifest with the changed source and exports. Run `pwsh -NoProfile -File tools/Build-Centurion.ps1` to build from the pinned files.
